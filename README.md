# OPSLands

Общая библиотека лендингов и подготовка ZIP под Cashfactorie / Lemonad. Node.js 24+.
Для текущей версии сначала выполните `pnpm install --frozen-lockfile` (pnpm 11.25.0). OIDC реализован библиотекой openid-client 6.8.8, шифрование серверного состояния — jose 6.2.12. Версии и integrity закреплены в lockfile.

## OpsVault SSO

Issuer: `https://portalwiki.world/sso`, клиент: `opslands`, callback: `https://land.portalwiki.world/auth/opsvault/callback`. Конфигурация и отдельный ключ шифрования хранятся только на сервере в `/etc/opslands-sso.env` (0600), читаются systemd EnvironmentFile. База до миграции сохранена в `/var/lib/opslands/backups/before-sso.sqlite`.

Вход доступен только через OpsVault, включая первый запуск с пустой базой. Парольный вход, локальная регистрация, создание пользователей администратором и старые URL связывания отключены (HTTP 410). Прежние парольные сессии завершаются; существующие OIDC-сессии сохраняются.

При первом входе активного пользователя OpsVault аккаунт OPSLands создается автоматически. Отдельный ServiceGrant для клиента `opslands` не требуется: эта политика должна быть установлена на стороне OpsVault. Роли OpsVault `admin`, `dev`, `owner` получают `admin` в OPSLands, остальные обычные пользователи — `member`. Роль проверяется центральной политикой при входе и последующих запросах, с кешем чтения до 60 секунд и свежей проверкой изменений. Неактивный пользователь, отключенный клиент или отозванная сессия доступа не получают; при недоступности OpsVault действия закрываются с 503.

JIT работает всегда, когда SSO настроен и включен (`SSO_ENABLED=1`); прежний флаг `SSO_JIT` больше не ограничивает создание аккаунтов. Новый пользователь получает отдельный ID и технические случайные реквизиты, сохраняемые в OpsVault для восстановления. Эти реквизиты не позволяют войти в OPSLands по паролю. Повторный вход использует связь issuer+subject; восстановление — сохраненные canonical credentials. Существующие связанные аккаунты сохраняют ID и владельцев лендов. Автоматического сопоставления несвязанных аккаунтов по имени/email нет; их данные не переносятся новому пользователю автоматически.

Удаление локального аккаунта завершает его сессии и сохраняет ленды. Следующий разрешенный вход через OpsVault создаст аккаунт заново; для отзыва доступа отключите пользователя в OpsVault. Локальный выход закрывает сервисную сессию; общий выход отзывает portal family.

Callbacks не пишутся в access/error log nginx; auth ответы no-store / no-referrer. Секреты, leases и passwords не должны попадать в Git или журналы. Пользовательская приемка реального связывания выполняется владельцем в браузере; операторская регистрация и тестовый callback не заменяют ее.

## Запуск

```powershell
node server.mjs
```

Открыть http://127.0.0.1:3000. Для другого порта: `$env:PORT = '3001'`.
Данные сохраняются в `data/opslands.sqlite` (SQLite с WAL). Перезапуск сохраняет ленды, партнерки и счетчики. Для резервной копии остановите сервер и скопируйте каталог `data`.

## Сервер

Рабочий адрес: https://land.portalwiki.world. Аккаунты и база перенесены из локальной версии. На новом домене нужно войти через OpsVault; cookie локального адреса браузер не переносит на домен.

- Приложение: `/opt/opslands/current`, отдельный Node.js 24: `/opt/opslands/node/bin/node`.
- База: `/var/lib/opslands/opslands.sqlite`, сервис работает от пользователя `opslands`.
- Постоянный запуск: `systemctl status opslands`; перезапуск: `systemctl restart opslands`; журнал: `journalctl -u opslands`.
- Nginx: `/etc/nginx/sites-available/opslands`, проксирует HTTPS на внутренний `127.0.0.1:3107`.
- Let's Encrypt: сертификат `land.portalwiki.world`, автоматическое продление через существующий `certbot.timer` и webroot `/var/www/opslands-acme`.
- Настройки: `OPSLANDS_ORIGIN=https://land.portalwiki.world`, `OPSLANDS_SECURE_COOKIE=1`, `OPSLANDS_TRUST_PROXY=1`. Последний параметр доверяет `X-Real-IP` только от локального прокси для ограничения неверных входов по IP клиента.

Конфигурации сохранены в `deploy/`. `deploy/install.sh` предназначен только для первого размещения и откажется перезаписывать существующее приложение или БД. При обновлении переносите исходники, сохраняя серверную БД. `scripts/package-release.py` делает согласованный SQLite снимок через backup API. Локальная и серверная базы после переноса независимы; повторно загружать локальную БД поверх рабочего сервера не следует.

## Что работает

- Каталог, поиск, фильтр по типу и языку, сортировка по скачиваниям / изменениям, вкладка своих лендов.
- Загрузка ZIP / HTML, сохранение ассетов, редактирование HTML, добавление или замена ресурса в новой версии.
- Новая версия получает собственный ID и ссылку на исходный ленд; исходник не меняется.
- Профили партнерок с настраиваемыми полями, обязательностью, именами полей формы и методом GET / POST.
- Генерация настоящего ZIP с параметрами конкретной сборки. Значения сборки не сохраняются в БД.
- Счетчик скачиваний — успешно сформированные архивы; счетчик изменений — непосредственно созданные дочерние версии. Это показатели использования, не конверсии.
- Изолированный предпросмотр HTML без выполнения скриптов и отправки формы.

Три начальных ленда помечены как демонстрационные; статистика начинается с нуля.

## Подготовить ленд

Раздел заменяет «Популярные». Загрузите ZIP (до 20 МБ), выберите ленд, если их несколько, затем партнерку. Для Cashfactorie нужны токен вебмастера, числовые ID оффера и потока; для Lemonad — токен и ID оффера. Реквизиты вводятся заново и не сохраняются в SQLite. Исходник и подготовленный вариант автоматически попадают в «Мои ленды», в одну группу с историей. ZIP целиком не хранится; сохраняются очищенные файлы без прежних PHP-обработчиков, скрытых реквизитов и журналов. Исходник сохраняет исходный вид страницы; рабочий обработчик добавляется при скачивании.

Результат — отдельный ZIP с `index.html`, ресурсами, `ops-submit.php`, серверным `ops-config.php`, скриптом переноса UTM/clickid/subid/fbpxl из URL и новой простой страницей благодарности. Все формы основного документа с полями `name` и `phone` переключаются на новый POST-обработчик. HTML разбирается parse5; ресурсы сохраняются. Удаляются прежние PHP-файлы, старые журналы и служебные файлы macOS. Произвольная PHP-логика основного документа и формы с onsubmit/formaction отклоняются. AJAX, формы на других страницах и нестандартные названия полей требуют отдельной адаптации. Старые пиксели страницы благодарности не переносятся.

Архив размещается на хостинге с **PHP 8.2+ и cURL**, с разрешением записи в каталог ленда. OPSLands не исполняет загруженный PHP и не отправляет заявки. HTTPS-проверка сертификата включена. Cashfactorie использует `/api/wm/push.json` и `status=ok` по предоставленному образцу; Lemonad — JSON POST на `https://sendmelead.com/api/v3/lead/add`, заголовок X-Token и `result=ok` по предоставленным журналам. Документация Lemonad: https://docs.limonad.com/doc/ru-lead-sending. Перед трафиком проверьте реальную заявку на целевом хостинге в кабинете партнерки. Хостинг должен исполнять `.php`, а не отдавать исходники.

Журнал находится **на хостинге ленда**, в `ops-logs/YYYY-MM-DD.php`: JSON-строки после PHP exit-защиты, запись с блокировкой. Поля: ID запроса, партнерка, оффер/поток, последние 4 символа телефона, наличие полей трекинга, HTTP-код, cURL-код, длительность, признак принятия и разрешенные поля ответа (status/result/localClickId/id/code). Имена, полные телефоны, API-токены, сырые запросы и ответы не пишутся. Для прокси нужно настроить правильный REMOTE_ADDR. Если журнал не удалось записать до отправки, заявка не отправляется. При таймауте или неизвестном ответе успех не показывается, автоматических повторов нет: сначала проверьте заявку в партнерке. Автоматического удаления старых журналов пока нет.

## Пользователи, доступ и сессии

При первом открытии создайте администратора: имя, логин и пароль (от 8 символов). Общего стандартного пароля нет. Первый администратор становится владельцем старых лендов: демо доступны всей команде, ранее загруженные шаблоны становятся личными.

Раздел «Администрирование» виден только администраторам. В нем можно создавать пользователей с ролями «Участник» / «Администратор», удалять аккаунты и видеть все ленды, включая личные. Управление профилями ПП также доступно только администраторам.

Участник видит свои и общие ленды. Новые ленды и версии по умолчанию личные; флажок «Показывать всем участникам команды» при загрузке или кнопка «Личный / Общий» на карточке меняет доступ. Владельцем становится авторизованный пользователь, а не имя из запроса. Доступ проверяется сервером для каталога, исходников, ресурсов предпросмотра, создания версии и скачивания ZIP. Администратор может менять видимость любого ленда.

Удаление пользователя отзывает все его сессии и сохраняет ленды: личные доступны администраторам, общие — всей команде. Нельзя удалить себя или последнего администратора.

Пароли хранятся как scrypt-хеши с индивидуальной солью. Сессии хранятся в SQLite, в браузере — случайный токен в HttpOnly / SameSite=Lax cookie. Срок — 180 дней с автоматическим продлением при активности, не чаще раза в день. Перезапуск сервера, перезагрузка страницы и закрытие обычного браузера сохраняют вход. Выход из аккаунта, удаление пользователя, истечение срока или очистка cookie требуют нового входа. Токены в БД хранятся только в виде SHA-256 хешей. Неверные попытки входа ограничены по IP.

На устройстве используется один активный аккаунт для этого адреса. Для переключения откройте профиль и нажмите «Выйти из аккаунта».

## Подготовка ленда

ZIP должен содержать основной HTML и ресурсы с относительными путями. Единая внешняя папка автоматически удаляется. Поддерживаются обычные ZIP Store / Deflate без пароля; до 500 файлов, 40 МБ после распаковки. Загрузка через интерфейс — до 20 МБ. HTML — UTF-8.

Один раз разметьте основную форму:

```html
<form action="{{form_action}}" method="{{form_method}}">
  {{hidden_fields}}
  <input name="name" required>
  <input name="phone" type="tel" required>
  <button type="submit">Отправить</button>
</form>
```

`{{hidden_fields}}` подставляет настроенные параметры ПП. `{{pp.offer_id}}` подставляет конкретное поле в HTML текст или значение атрибута, заключенное в кавычки. Такие маркеры не предназначены для JavaScript, CSS или серверного кода. HTML значения экранируются.

При загрузке ZIP снимите «Использовать HTML из редактора»: основной HTML берется из архива. Чтобы разметить импортированный шаблон, откройте его через кнопку редактирования и сохраните новую версию. При замене картинки укажите путь, используемый в HTML.

## Границы первого этапа

В сборке из каталога реализовано прямое подключение HTML формы к HTTP(S) обработчику. Поля заявки — `name` и `phone`. Для ПП, требующей PHP обработчик, переименование полей заявки, подпись, серверный API ключ или нестандартный запрос, потребуется адаптер под ее спецификацию. В существующем архиве PHP / JS файлы сохраняются, но их интеграция автоматически не изменяется. Перед реальным запуском нужна тестовая заявка на целевом хостинге.

Сервер слушает только 127.0.0.1. Перед размещением для команды нужны HTTPS, конфигурация домена, инфраструктура хранения и резервного копирования. За HTTPS включите `OPSLANDS_SECURE_COOKIE=1`; локально используется HTTP. Секреты серверных API не следует помещать в экспортируемый HTML. Самостоятельный сброс забытого пароля пока не реализован.

Unilands отложен до следующего этапа. Каталог / версии / профили ПП выделены в самостоятельные сущности. Сейчас HTML редактор, без визуального конструктора.

## ИИ-адаптация через OpenRouter

В боковине есть раздел «Адаптация лендинга» перед «Моими лендами». После ZIP выбираются index и партнерка, затем пользователь пишет один основной промпт, например: «Под Турцию на турецком; герой — Мехмет; на выбранных картинках турецкая квартира». Отдельных полей страны и языка нет. Небольшой структурированный запрос определяет параметры из промпта, после чего они применяются ко всем частям текста или изображениям. У существующей версии можно сохранить ее гео/язык, если промпт их не меняет. Неоднозначный запрос останавливается с предложением уточнить промпт; определение параметров тоже может быть платным и включается в лимит.

В окне два независимых действия: «Адаптировать тексты» и «Адаптировать изображение». Первое не меняет картинки, второе — тексты. Чтобы последовательно изменить оба, откройте сохраненный результат → «Продолжить адаптацию»: следующий этап берет файлы этой версии и остается в группе исходного ленда. Старые API-клиенты с явными country/language и смешанным заданием поддерживаются для совместимости.

Перед запуском показана диагностика именно выбранного index: число фрагментов, объем текста, число частей для модели, используемые/остальные изображения и внешние ссылки. Поддерживается **до 20000 фрагментов и 1 МиБ текстовых данных** вместо прежних 1500/36 КБ. Текст разбивается на части до 100 фрагментов/10000 байт; длинные отдельные узлы тоже делятся, их переводы собираются перед безопасной вставкой. При превышении предела сообщаются фактическое значение, ограничение и способ исправления. Если текста нет или он слишком большой, работа с доступными изображениями остается возможной. При недостаточном бюджете ошибка показывает объем ленда, количество частей/картинок, требуемый резерв и доступный лимит.

Перевод работает по разрешенным текстовым фрагментам основного документа: модель не получает разметку, скрипты, форму или серверные файлы. Все ID проверяются; ответ экранируется. Меняется `lang`, сохраняются пробелы по краям текстовых узлов. Тексты в JS, вторичные страницы и произвольная PHP-логика требуют отдельной адаптации. Это не визуальный редактор и не гарантия юридической или фактической корректности текста.

Изображения показаны двумя группами с индивидуальными галочками и выбором всей группы: **используются в index** (img, picture/source, srcset, lazy-src, inline CSS и фоны связанных CSS, включая локальные @import) и **другие файлы ZIP**. Один ресурс показан один раз. Вторая группа может использоваться JavaScript или другими страницами — это не утверждение, что файл нигде не нужен. Внешние изображения не скачиваются; их количество видно в диагностике. Картинки из других папок выбранного ленда доступны независимо от наличия img в index.

Над списками есть отдельный общий промпт для всех выбранных картинок (до 4000 символов), а под каждым изображением — необязательное индивидуальное уточнение (до 2000). Для каждого запроса складываются контекст основного промпта, общие указания для картинок и только уточнение этого файла; индивидуальные указания имеют приоритет при конфликте с общими. Пожелания для невыбранных файлов не отправляются. При изменении партнерки набранные уточнения сохраняются для того же index и пути. Для режима изображений основной промпт может быть пустым, если есть общий промпт для картинок или уточнения ко всем выбранным файлам. Секреты, контакты, слишком длинные значения и уточнения к чужим/невыбранным ID отклоняются до платных запросов.

После нажатия кнопка сразу показывает вращающийся индикатор и «Отправляем изображения…», блокируется повторное нажатие. После постановки в очередь индикатор остается возле выполняющегося задания; виден текущий этап и имя обрабатываемого файла. При завершении, отмене или ошибке индикатор исчезает. Ошибка отправки возвращает кнопку в обычное состояние.

Кнопка адаптации изображений отправляет только выбранные статичные PNG/JPEG/WebP/GIF/AVIF в OpenRouter как `input_references`, предварительно удалив метаданные/EXIF и ограничив размер образца. Sharp 0.35.5 проверяет декодирование и лимит 16 Мп; входной файл — до 8 МБ. SVG/BMP/ICO и анимация пока не редактируются; причина отображается или возвращается с именем файла. Результат перекодируется обратно в исходный формат и размер, записывается по прежнему пути: ссылки HTML/CSS/JS не надо менять, включая srcset. Можно выбрать до 100 файлов, но реальное число ограничено бюджетом, размером ZIP и общим объемом очищенных образцов 32 МБ. Выбранное изображение само по себе может содержать видимые персональные сведения — пользователь должен проверить содержимое перед отправкой.

Настройки задаются **только окружением серверного процесса**, ключ не доступен браузеру:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `OPENROUTER_API_KEY` | отсутствует, ИИ отключен | Отдельный ключ OpenRouter с лимитом расходов |
| `OPSLANDS_AI_TEXT_MODELS` | `qwen/qwen3-235b-a22b-2507,deepseek/deepseek-v3.2,google/gemini-2.5-flash` | Разрешенные текстовые модели через запятую |
| `OPSLANDS_AI_IMAGE_MODELS` | `bytedance-seed/seedream-4.5,sourceful/riverflow-v2-fast` | Разрешенные модели изображений через запятую |
| `OPSLANDS_AI_MAX_JOB_USD` | `0.5` | Максимальный лимит задания, жесткий максимум приложения $2 |
| `OPSLANDS_AI_DAILY_USD` | `3` | Суточный резерв всей команды, сутки UTC |
| `OPSLANDS_AI_INPUT_USD_PER_M` | `1` | Максимальная цена миллиона входных текстовых токенов |
| `OPSLANDS_AI_OUTPUT_USD_PER_M` | `5` | Максимальная цена миллиона выходных текстовых токенов |

Выбор проверен по публичному каталогу и официальной документации OpenRouter 17 ноября 2026 года. [Qwen3 235B Instruct](https://openrouter.ai/qwen/qwen3-235b-a22b-2507) выбран первым как многоязычная модель без режима размышлений; [DeepSeek V3.2](https://openrouter.ai/deepseek/deepseek-v3.2) и Gemini 2.5 Flash доступны как альтернативы. Все три объявляют поддержку структурированных ответов в каталоге. Это варианты для сравнения качества и доступности, а не обещание отсутствия модерации. Qwen проверен в реальном тесте; новые проверки изменений этого окна используют mock OpenRouter без расходов. Seedream 4.5 имеет endpoint с фиксированными $0,04 за изображение. Для сравнения добавлен [Riverflow V2 Fast](https://openrouter.ai/sourceful/riverflow-v2-fast): $0,02 за 1K или $0,04 за 2K. Резерв консервативно суммирует опубликованные выходные тарифы и возможную фиксированную плату за один входной образец. Шрифты и специальные улучшения не запрашиваются; если модель тарифицирует их как входной reference, эта цена также зарезервирована. Модели можно заменить без изменения кода. Текстовая модель должна поддерживать `max_tokens`, `temperature`, `response_format/json_schema`; провайдер обязан принять эти параметры. Для изображений допускаются только endpoints с проверяемой фиксированной ценой за изображение: модели с оплатой за токен или мегапиксель отклоняются, включая Gemini Flash Image. Перед каждой картинкой цена и провайдер проверяются заново. Сведения: [модели](https://openrouter.ai/api/v1/models), [структурированные ответы](https://openrouter.ai/docs/guides/features/structured-outputs), [Image API](https://openrouter.ai/docs/guides/overview/multimodal/image-generation), [маршрутизация](https://openrouter.ai/docs/guides/routing/provider-selection).

Расход ограничивается до постановки в очередь: резерв по байтовой верхней оценке входа, до 400 выходных токенов для определения параметров и 6000 для каждой части текста, текущей фиксированной цене выбранных картинок и их входных образцов и запасу 10%. Резерв должен укладываться в пользовательский и серверный лимит. Для текста передается `provider.max_price`, для картинок фиксируется один провайдер без fallback; инструменты, поиск и платные повторы не включаются. Одна платная попытка на определение параметров, каждую часть текста и каждую картинку. До 100 выбранных изображений в пределах бюджета; автоматических повторов нет. HTTP 401/402/403/429 останавливает задание с пояснением; запрет провайдера по условиям использования не обходится автоматической сменой модели. **Резерв — консервативная оценка, не платежная гарантия провайдера**: для абсолютного ограничения счета задайте hard limit отдельного API-ключа в OpenRouter. Отмена или таймаут не гарантируют возврат денег; их резерв не освобождается. Дневной счетчик хранится в SQLite и переживает перезапуски. Фактическая стоимость показывается только если провайдер вернул ее для всех этапов.

Задания доступны только создателю, включая администратора, работающего со своим списком. Авторизация и OpsVault SSO проверяются на API чтения, отмены, предпросмотра и скачивания. Очередь — максимум пять заданий на процесс, одно активное задание пользователя, последовательное выполнение с общим таймаутом 30 минут и пределом четыре минуты на отдельный запрос. Поддерживается один серверный процесс на БД. При перезапуске незавершенные задания отмечаются прерванными, автоматического возобновления с расходами нет. Пользователь видит безопасное сообщение об ошибке без сырого ответа провайдера. Временные результаты задания хранятся 24 часа; при запросе и раз в минуту удаляется их содержимое. При запуске исходник сохраняется в личной библиотеке, а успешная адаптация сохраняется туда сразу после генерации, до скачивания. Эти библиотечные копии не удаляются по сроку задания. Они сгруппированы в «Моих лендах» по исходнику; доступны пометки этапа, предпросмотры «до / после» и повторное скачивание с новыми реквизитами. Повторная подготовка одинаковых файлов не создает дубликаты исходника и результата. Ранее готовые задания импортируются при запуске приложения, пока их файлы доступны; если старый исходник не сохранялся, он не восстанавливается вымышленной копией. Раньше скачанные подготовленные ZIP восстановить из базы нельзя — их нужно загрузить заново. Метаданные и резервы удаляются через 32 дня. SQLite/WAL и резервные копии требуют обычной политики доступа и удаления: удаление записи не означает криптографическое стирание старых копий.

Перед отправкой контента провайдеру PHP-обработчики, журналы, `.env` и служебные файлы исключаются подготовкой. Запрос формируется из разрешенных текстовых узлов, `placeholder`, `alt` и `title`; скрытые поля, скрипты, стили и значения полей не передаются. Выбранные изображения передаются только в режиме их адаптации, очищенными от метаданных; все остальные картинки остаются локально в ресурсах ленда. Фрагменты с контактами, длинными ключами и признаками реквизитов отбрасываются. В пожелания нельзя вводить контакты и секреты; автоматическая фильтрация не заменяет проверку содержимого пользователем. Используется `data_collection: deny` (не обучение; это не обещание нулевого хранения). Исходные страницы могут содержать произвольные персональные сведения в обычном тексте — перед загрузкой удалите их. Настоящие реквизиты партнерки вводятся только при скачивании: PHP-конфиг добавляется в поток ZIP и не сохраняется в задании. Предпросмотр запрещает JS, внешние ресурсы и отправку форм; PHP и конфиг не отдаются. После размещения ZIP на PHP 8.2+ хостинге обязательно проверьте реальную тестовую заявку, скрипты и перевод.

Локально можно передать ключ через `OPENROUTER_API_KEY` и запустить `node server.mjs`. Не записывайте ключ в репозиторий или клиентский JS. Файл Windows DPAPI не переносится на Linux: для серверного запуска задайте отдельную защищенную переменную окружения. Шаблон systemd читает необязательный `/etc/opslands-ai.env`; храните его с правами `0600`. Применение конфигурации и перезапуск выполняются отдельно при согласованной выкладке. Обновление кода само по себе не выкатывает и не включает ИИ на рабочем сервере.

Проверка с реальным провайдером запускается только явно: `node scripts/ai-smoke.mjs` при заданном `OPENROUTER_API_KEY`. Она использует синтетический ленд, максимум $0,15 и без повторов. Для одной картинки дополнительно задайте `AI_SMOKE_IMAGES=1`. Реальные архивы, ключи и журналы для проверки не используются. Основные тесты используют mock OpenRouter и денег не расходуют.

## Проверки

```powershell
node --test test/*.test.mjs
```

Проверяются ZIP и бинарные ассеты, пути архива, подстановки, валидация ПП, импорт, неизменность исходника, счетчики, разграничение доступа, автоматическое создание / удаление пользователей, отзыв и продление сессий, сохранение после перезапуска. Интеграционные тесты используют временную БД и отдельный порт.

Дополнительная проверка интерфейса: `node scripts/browser-check.mjs`. Она требует переменных `PLAYWRIGHT_MODULE` (полный путь к модулю Playwright `index.mjs`) и `BROWSER_PATH` (путь к Chromium / Edge), использует отдельную временную БД и сохраняет снимки экрана в `data/qa`. Проверяет вход только через OpsVault на пустой базе, отсутствие парольных полей, поиск, реальное скачивание, создание версии и партнерки, мобильную ширину и отсутствие ошибок JavaScript.

Для проверки сгенерированного обработчика на настоящем PHP задайте `PHP_PATH` (путь к PHP CLI с cURL). На Windows дополнительно `PHP_EXT_DIR` для каталога расширений. Затем выполните общую команду тестов. Тест использует только локальный mock API, проверяет оба протокола, ошибки и защищенные журналы. Без PHP_PATH этот тест пропускается; CI устанавливает PHP и выполняет его.

Отказ HTTP 403 с сообщением о provider Terms Of Service отличается от недостаточного баланса. Даже с положительным балансом провайдер может ограничить модель, аккаунт или доступ по своим условиям. В проверке прежнего запуска тот же отказ пришел на «Say OK», поэтому причина в содержимом ленда не установлена. Проверять нужно доступ в OpenRouter Activity и через поддержку; повторное пополнение само по себе не устраняет такой запрет. См. [официальные ошибки](https://openrouter.ai/docs/api_reference/errors-and-debugging). Автоматической смены модели после отказа нет.

При адаптации разрешено удалить отдельную фразу, вернув пустой текст для ее ID: это нужно, например, при удалении неподтвержденной гарантии. Все ID остаются обязательными, полностью пустая страница отклоняется. Ошибка проверки указывает только ID и категорию проблемы, без содержимого фрагмента. Известная стоимость текстового ответа сохраняется до проверки результата, поэтому платный ответ, отклоненный проверкой, не выглядит бесплатным. Для текста выбирается наиболее быстрый подходящий endpoint в пределах заданной цены, без fallback.

Для рабочего потолка $0,50 задайте `OPSLANDS_AI_MAX_JOB_USD=0.50`. Суточный резерв должен позволять такие задания: при тестовом общем ограничении используйте `OPSLANDS_AI_DAILY_USD=0.50`. Эти пределы независимы, а ранее зарезервированные задания продолжают учитываться. Начальный лимит в окне — максимум $0,50 в пределах настройки сервера; пользователь может уменьшить его до запуска.
