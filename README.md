# OPSLands

Общая библиотека лендингов. Node.js 24+.
Для текущей версии сначала выполните `pnpm install --frozen-lockfile` (pnpm 11.25.0). OIDC реализован библиотекой openid-client 6.8.8, шифрование серверного состояния — jose 6.2.12. Версии и integrity закреплены в lockfile.

## OpsVault SSO

Issuer: `https://portalwiki.world/sso`, клиент: `opslands`, callback: `https://land.portalwiki.world/auth/opsvault/callback`. Конфигурация и отдельный ключ шифрования хранятся только на сервере в `/etc/opslands-sso.env` (0600), читаются systemd EnvironmentFile. База до миграции сохранена в `/var/lib/opslands/backups/before-sso.sqlite`.

На странице входа доступны OpsVault и отдельный пароль OPSLands. Для существующего пользователя: войти локально → профиль → «Связать OpsVault» → ввести текущий пароль OPSLands и согласиться сохранить его в OpsVault → пройти вход портала → подтвердить оба показанных аккаунта. ID, login, hash пароля и ownerId лендов сохраняются; прежние сессии после связи отзываются. Обычный повторный OIDC вход не требует повторного связывания.

Роль связанного пользователя поступает только из ServiceGrant. Связанный парольный вход требует центральный local-access; OIDC-сессия — access по зашифрованному lease. Чтение кешируется максимум 60 секунд от начала запроса, изменения проверяются свежим запросом. Отзыв закрывает сессию; outage запрещает действия с 503. Gateoff не открывает локальный обход для связанного пользователя.

Автоматическое создание аккаунтов включено (`SSO_JIT=1`). Новый пользователь с действующим ServiceGrant получает отдельный ID, случайные логин и пароль OPSLands; реквизиты публикуются в его хранилище OpsVault перед сохранением локального аккаунта. Повторный вход использует ту же связь issuer+subject, а recovery — ранее сохраненные canonical credentials. Без разрешения аккаунт не создается. Роль приходит из ServiceGrant, разрешения автоматически не выдаются.

Первоначальный администратор OpsVault: `karlmichael`. Существующие аккаунты необходимо связывать явно через профиль. Если в браузере уже активна несвязанная локальная сессия, обычный OIDC вход предложит связывание вместо нового аккаунта. Сопоставления по именам или email нет. Несвязанный существующий local admin оставлен как аварийный доступ; после связи он также подчиняется центральной политике. Перед включением JIT сохранена копия `/var/lib/opslands/backups/before-jit.sqlite`. Для управления флагом без смены ключей и grants предусмотрен `deploy/enable-jit.py`.

Пароль OpsVault не передается OPSLands. Пароль OPSLands временно хранится только в зашифрованном pending (5 минут), затем публикуется в собственную карточку OpsVault и удаляется из pending. В сервисе остается hash. Самостоятельная смена реквизитов связанного пользователя не реализована и не предлагается. Локальный выход закрывает сервисную сессию; общий выход доступен только OIDC-сессии и отзывает ее portal family.

Callbacks не пишутся в access/error log nginx; auth ответы no-store / no-referrer. Секреты, leases и passwords не должны попадать в Git или журналы. Пользовательская приемка реального связывания выполняется владельцем в браузере; операторская регистрация и тестовый callback не заменяют ее.

## Запуск

```powershell
node server.mjs
```

Открыть http://127.0.0.1:3000. Для другого порта: `$env:PORT = '3001'`.
Данные сохраняются в `data/opslands.sqlite` (SQLite с WAL). Перезапуск сохраняет ленды, партнерки и счетчики. Для резервной копии остановите сервер и скопируйте каталог `data`.

## Сервер

Рабочий адрес: https://land.portalwiki.world. Аккаунты и база перенесены из локальной версии. На новом домене нужно один раз войти прежним логином и паролем; cookie локального адреса браузер не переносит на домен.

- Приложение: `/opt/opslands/current`, отдельный Node.js 24: `/opt/opslands/node/bin/node`.
- База: `/var/lib/opslands/opslands.sqlite`, сервис работает от пользователя `opslands`.
- Постоянный запуск: `systemctl status opslands`; перезапуск: `systemctl restart opslands`; журнал: `journalctl -u opslands`.
- Nginx: `/etc/nginx/sites-available/opslands`, проксирует HTTPS на внутренний `127.0.0.1:3107`.
- Let's Encrypt: сертификат `land.portalwiki.world`, автоматическое продление через существующий `certbot.timer` и webroot `/var/www/opslands-acme`.
- Настройки: `OPSLANDS_ORIGIN=https://land.portalwiki.world`, `OPSLANDS_SECURE_COOKIE=1`, `OPSLANDS_TRUST_PROXY=1`. Последний параметр доверяет `X-Real-IP` только от локального прокси для ограничения неверных входов по IP клиента.

Конфигурации сохранены в `deploy/`. `deploy/install.sh` предназначен только для первого размещения и откажется перезаписывать существующее приложение или БД. При обновлении переносите исходники, сохраняя серверную БД. `scripts/package-release.py` делает согласованный SQLite снимок через backup API. Локальная и серверная базы после переноса независимы; повторно загружать локальную БД поверх рабочего сервера не следует.

## Что работает

- Каталог, поиск, фильтр по типу и языку, сортировка по скачиваниям / изменениям, вкладка своих лендов.
- Загрузка ZIP / HTML, сохранение ассетов, редактирование HTML, добавление или замена ресурса в новой версии.
- Новая версия получает собственный ID и ссылку на исходный ленд; исходник не меняется.
- Профили партнерок с настраиваемыми полями, обязательностью, именами полей формы и методом GET / POST.
- Генерация настоящего ZIP с параметрами конкретной сборки. Значения сборки не сохраняются в БД.
- Счетчик скачиваний — успешно сформированные архивы; счетчик изменений — непосредственно созданные дочерние версии. Это показатели использования, не конверсии.
- Изолированный предпросмотр HTML без выполнения скриптов и отправки формы.

Три начальных ленда помечены как демонстрационные; статистика начинается с нуля.

## Пользователи, доступ и сессии

При первом открытии создайте администратора: имя, логин и пароль (от 8 символов). Общего стандартного пароля нет. Первый администратор становится владельцем старых лендов: демо доступны всей команде, ранее загруженные шаблоны становятся личными.

Раздел «Администрирование» виден только администраторам. В нем можно создавать пользователей с ролями «Участник» / «Администратор», удалять аккаунты и видеть все ленды, включая личные. Управление профилями ПП также доступно только администраторам.

Участник видит свои и общие ленды. Новые ленды и версии по умолчанию личные; флажок «Показывать всем участникам команды» при загрузке или кнопка «Личный / Общий» на карточке меняет доступ. Владельцем становится авторизованный пользователь, а не имя из запроса. Доступ проверяется сервером для каталога, исходников, ресурсов предпросмотра, создания версии и скачивания ZIP. Администратор может менять видимость любого ленда.

Удаление пользователя отзывает все его сессии и сохраняет ленды: личные доступны администраторам, общие — всей команде. Нельзя удалить себя или последнего администратора.

Пароли хранятся как scrypt-хеши с индивидуальной солью. Сессии хранятся в SQLite, в браузере — случайный токен в HttpOnly / SameSite=Lax cookie. Срок — 180 дней с автоматическим продлением при активности, не чаще раза в день. Перезапуск сервера, перезагрузка страницы и закрытие обычного браузера сохраняют вход. Выход из аккаунта, удаление пользователя, истечение срока или очистка cookie требуют нового входа. Токены в БД хранятся только в виде SHA-256 хешей. Неверные попытки входа ограничены по IP.

На устройстве используется один активный аккаунт для этого адреса. Для переключения откройте профиль и нажмите «Выйти из аккаунта».

## Подготовка ленда

ZIP должен содержать основной HTML и ресурсы с относительными путями. Единая внешняя папка автоматически удаляется. Поддерживаются обычные ZIP Store / Deflate без пароля; до 500 файлов, 40 МБ после распаковки. Загрузка через интерфейс — до 20 МБ. HTML — UTF-8.

Один раз разметьте основную форму:

```html
<form action="{{form_action}}" method="{{form_method}}">
  {{hidden_fields}}
  <input name="name" required>
  <input name="phone" type="tel" required>
  <button type="submit">Отправить</button>
</form>
```

`{{hidden_fields}}` подставляет настроенные параметры ПП. `{{pp.offer_id}}` подставляет конкретное поле в HTML текст или значение атрибута, заключенное в кавычки. Такие маркеры не предназначены для JavaScript, CSS или серверного кода. HTML значения экранируются.

При загрузке ZIP снимите «Использовать HTML из редактора»: основной HTML берется из архива. Чтобы разметить импортированный шаблон, откройте его через кнопку редактирования и сохраните новую версию. При замене картинки укажите путь, используемый в HTML.

## Границы первого этапа

Сейчас реализовано прямое подключение HTML формы к HTTP(S) обработчику. Поля заявки — `name` и `phone`. Для ПП, требующей PHP обработчик, переименование полей заявки, подпись, серверный API ключ или нестандартный запрос, потребуется адаптер под ее спецификацию. В существующем архиве PHP / JS файлы сохраняются, но их интеграция автоматически не изменяется. Перед реальным запуском нужна тестовая заявка на целевом хостинге.

Сервер слушает только 127.0.0.1. Перед размещением для команды нужны HTTPS, конфигурация домена, инфраструктура хранения и резервного копирования. За HTTPS включите `OPSLANDS_SECURE_COOKIE=1`; локально используется HTTP. Секреты серверных API не следует помещать в экспортируемый HTML. Самостоятельный сброс забытого пароля пока не реализован.

Unilands и ИИ отложены до второго этапа. Каталог / версии / профили ПП выделены в самостоятельные сущности для дальнейшего расширения. Сейчас HTML редактор, без визуального конструктора.

## Проверки

```powershell
node --test test/*.test.mjs
```

Проверяются ZIP и бинарные ассеты, пути архива, подстановки, валидация ПП, импорт, неизменность исходника, счетчики, разграничение доступа, создание / удаление пользователей, отзыв и продление сессий, сохранение после перезапуска. Интеграционные тесты используют временную БД и отдельный порт.

Дополнительная проверка интерфейса: `node scripts/browser-check.mjs`. Она требует переменных `PLAYWRIGHT_MODULE` (полный путь к модулю Playwright `index.mjs`) и `BROWSER_PATH` (путь к Chromium / Edge), использует отдельную временную БД и сохраняет снимки экрана в `data/qa`. Проверяет поиск, реальное скачивание, создание версии и партнерки, мобильную ширину и отсутствие ошибок JavaScript.
